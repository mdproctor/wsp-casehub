# Formation Memory Grounding in Drive Descriptions

**Issue:** casehubio/neocortex#735
**Branch:** issue-735-formation-memory-grounding
**Date:** 2026-11-03

## Problem

Drive descriptions generated by `DriveDescriptionGenerationPhase` (P22) don't incorporate formation memories deeply enough for dialogue-form scenes. Characters score formation echo >= 4 in aside-form but = 1 in dialogue-form.

Root cause: the P22 system prompt weights BODY TERRITORY and CONTRAST as the dominant signals ("CONTRAST... is the single most important differentiator"), while formation memory grounding is a single weak line at the end ("Ground in specific formation memories where possible"). The user prompt passes formation memories as a simple numbered list with no instruction on how to render them.

In aside-form scenes, the LLM has prose room to independently develop formation memories into body sensations. In dialogue-form (one dense paragraph), there's no room — the formation memory has to already be embedded as a body echo in the drive description itself, or it gets dropped.

## Scope

Changes are confined to `DriveDescriptionGenerationPhase.java` in `neocortex/mindmap-intelligence`. Specifically:
- The `SYSTEM_PROMPT` constant (lines 55-85)
- The user prompt construction in `callLlm()` (lines 398-403)

No changes to downstream consumers (`CognitionObservationBuilder`, `CharacterAgentLoop`, etc.) — they read and inject the `generated-description` property verbatim.

## Design

### System prompt restructuring

Replace the current emphasis hierarchy with a formation-memory-anchored structure:

**Current hierarchy** (implicit, by prompt position and emphasis):
1. Body territory (bold header, "START the description with...")
2. Contrast (bold header, "the single most important differentiator")
3. Four channels (detailed list)
4. Formation memories ("Ground in... where possible" — one line, end of prompt)

**New hierarchy:**
1. Formation memory body echo (lead with: "START with what the body learned from the formation memories — not what happened, but the somatic imprint left behind")
2. Body territory (required location anchor, but not the opening beat)
3. Four channels (woven as texture, unchanged)
4. Contrast (brief, demoted from "single most important" to "note briefly")

Key prompt changes:
- Move formation memory instruction from end to top, making it the organizing principle
- Change "Ground in specific formation memories where possible" to a mandatory requirement: when formation memories are provided, each description must include at least one rendered as a body sensation. When no formation memories exist for a drive, fall back to personality-and-attachment-derived somatic description (existing behaviour)
- Add explicit anti-pattern guidance: "NOT 'like when you were ten' — instead 'your body remembers [specific sensation from that memory]'"
- Demote CONTRAST from bold-header emphasis to inline instruction
- Keep body territory as required location, but as the container for the formation echo rather than the primary content
- Keep 3-5 sentence budget unchanged

### User prompt restructuring

**Current** (lines 398-403):
```
Formation memories that shaped this pull:
1. Your father knelt to help the stranger
```

**New:**
```
Formation memories — describe what the body LEARNED from each, not what happened:
1. Your father knelt to help the stranger
   → What does your body do NOW when this pull arrives, because of this memory?
```

The arrow instruction for each memory forces the LLM to think about somatic encoding rather than narrative reference.

### Test changes

Update existing tests in `DriveDescriptionGenerationPhaseTest`:
- `promptIncludesFormationMemoriesAndDriveContext` — verify the new prompt structure includes the somatic rendering instruction
- Add a new test `promptRequestsFormationMemoryAsSomaticEcho` — verify the system prompt contains the formation-memory-first instruction and the anti-pattern guidance

No new LLM eval tests are needed in this change — the existing formation echo scoring in the eval framework (classify_emotions.py) will measure the impact on actual scenario runs.

## Acceptance Criteria (from issue)

- P22-generated drive descriptions include at least one formation memory echo per drive
- Formation memories appear as body sensations ("my body remembers the window ledge under my forearms") not citations ("like when I was ten")
- Dialogue-form scenes score formation echo >= 3
